Every study of word recognition begins with a list of words, and every reviewer of such a study asks how the list was made. In a contrast between high- and low-frequency words, the two conditions have to be equated on length, on orthographic neighbourhood and on whatever else predicts reading times, and when the items are dealt into counterbalancing lists, the lists have to be equated too, or the groups that receive them differ in the materials before they differ in anything else. Packages such as LexOPS match words but stop short of the experiment, and experiment builders present stimuli without matching them. In the studies I have worked on, the two halves were joined by hand, in scripts that no one else could run.

lexsync joins the two halves. From a word-frequency corpus in any of dozens of languages, it selects items matched in parallel on several dimensions, counterbalances them across conditions and lists, generates pseudowords where the paradigm needs them, and writes the experiment for PsychoPy, OpenSesame or the browser through jsPsych, with electroencephalography (EEG) triggers bound to the screen refresh on which the stimulus appears. It ships as two packages of the same name, one in R and one in Python, built from one repository and released under one version, and under its deterministic matching methods the two engines select byte-identical stimuli. Nothing in either package draws a random number: trial order and jitter come from keyed SHA-256 hashes of the design and the seed, which is what allows a seeded shuffle to mean the same thing in both languages. The post runs the R package on the English lexicon bundled with it and closes by running the Python package on the same design files. Both packages are installed from GitHub, which also hosts the R and Python documentation.

The pool

The bundled lexicon carries a Zipf frequency (van Heuven et al., 2014), the orthographic neighbourhood density N and OLD20 (Yarkoni et al., 2008) for each word, and loading it adds length and an orthographic estimate of syllable count. The estimate is worth inspecting before it is used, since it counts vowel runs and so scores ‘rhythm’ and ‘being’ as one syllable and ‘chocolate’ as four.

A design is a list, or a YAML file, that names the conditions, the dimensions to match and the number of items, together with the filters that narrow the lexicon to a candidate pool. The pool has to be built explicitly, since the matching functions never read the filters themselves.

design_freq <- list(
  name = 'blog_freq', language = 'english',
  n_per_condition = 40,
  pool_filters = list(length = c(3, 7), frequency = c(3.8, 7.0)),

#> [1]  71 480

What the matching achieved

A statement that two conditions were matched is a claim about a difference being small, and the usual test of the difference against zero cannot support it. The match report therefore gives, for each dimension, Cohen’s d with a 90% confidence interval, the variance ratio and an equivalence test of the two one-sided kind (Lakens, 2017) against the schema’s bound of half a standard deviation. The manipulated dimension, frequency, shows the size of the manipulation.

report <- match_report(stim, c('frequency', 'length', 'n_density', 'old20'), schema)

The verdicts depend on the number of items as much as on the means. With 20 items per condition, the same design gives a confidence interval of about ±0.53 on every d, and every equivalence test fails against the 0.5 bound although the point estimates stay near zero. The interval is the quantity to report.

Lists that are themselves balanced

Dealing the matched sets into two lists by rank leaves the lists unequal in neighbourhood density, which matters when, as in a study of learners of a third language, the lists are crossed with a between-participants group. The balancing step runs an integer descent that swaps item sets between lists until no single exchange lowers the imbalance, with a keyed-hash tie-break so that the result is the same in both engines.

bl <- balance_lists(stim, design_freq, schema)
c(cost_before = bl$report$cost_before, cost_after = bl$report$cost_after,
  swaps = bl$report$n_swaps)
#> cost_before  cost_after       swaps 
#>      743080       17880           5
plain    <- counterbalance(stim, list(counterbalance = list(lists = 2)), schema)
balanced <- counterbalance(stim, design_freq, schema, bl$list_of_set)

                                  by = list(list = d$list), FUN = function(x) round(mean(x), 3))

Pseudowords and a lexical-decision trial

A lexical-decision task needs foils. The default generator substitutes letters under the constraint that every bigram of the result is attested in the reference lexicon, which keeps the foil close to its base word, whereas the subsyllabic generator, after Wuggy (Keuleers & Brysbaert, 2010), swaps whole onsets, nuclei and codas, which preserves syllabic structure at some cost to visual similarity. Both generators are deterministic, so a given base word always yields the same foil.

ld_pool <- build_pool(lex, list(length = c(4, 7), frequency = c(3.5, 6.0)))
nrow(ld_pool)
#> [1] 1038
ls8 <- build_lexdec_stimuli(ld_pool, n = 8, reference_words = lex$word)
ss8 <- build_lexdec_stimuli(ld_pool, n = 8, reference_words = lex$word,
                            method = 'subsyllabic')

A trial is described in the design file as a sequence of events. The design below has four, a fixation cross, the target with an onset-locked condition trigger, a keyboard response and a blank whose duration is jittered per trial between 400 and 800 ms and stored as the inter-trial interval. The same description drives all three experiment targets.

design_ld <- list(
  name = 'blog_lexdec', language = 'english', paradigm = 'lexical_decision',
  items = list(source = 'generate', lexicon = lexicon_path),
  n_per_condition = 40,
  pool_filters = list(length = c(4, 7), frequency = c(3.5, 6.0)),
  events = list(
    list(type = 'fixation', content = '+', duration_ms = 500),
    list(type = 'text', content = '{target}', duration_ms = 800,
         trigger = 'condition', onset_locked = TRUE),
    list(type = 'response', keys = c('f', 'j'), timeout_ms = 2000),
    list(type = 'blank', duration = list(jitter = c(400, 800), as = 'iti_ms'))),
  counterbalance = list(lists = 2))
ld <- build_lexdec_stimuli(ld_pool, n = design_ld$n_per_condition,
                           reference_words = lex$word)
ld <- counterbalance(ld, design_ld, schema)
ld <- resolve_trial_timing(ld, design_ld, schema)
ld <- assign_triggers(ld)

The same design files, in one call, in both engines

The Python package reads its own bundled copies of the lexicon and the schema, which are byte-identical to the R ones, runs the same two design files and prints the same checksums, shortened here to their first 16 hexadecimal digits. The datasheets and run logs differ by design, since they record the engine, the package versions and the time.

import hashlib, os
from importlib.resources import files
import lexsync

data = files('lexsync') / 'data'
schema_path, lexicon_path = str(data / 'schema.yaml'), str(data / 'en_example.csv')
out = os.path.join(os.environ['LEXSYNC_POST_OUT'], 'python')
os.makedirs(out, exist_ok=True)

def sha256(path):
    with open(path, 'rb') as fh:
        return hashlib.sha256(fh.read()).hexdigest()[:16]

designs = {}
for name in ('blog_freq', 'blog_lexdec'):
    src = os.path.join(os.environ['LEXSYNC_POST_OUT'], f'design_{name}.yaml')
    with open(src, encoding='utf-8') as fh:
        text = fh.read()
    # The only line that differs between the engines names the bundled lexicon.
    text = '\n'.join(
        line.split('lexicon:')[0] + 'lexicon: ' + lexicon_path if 'lexicon:' in line else line
        for line in text.splitlines()) + '\n'
    designs[name] = os.path.join(out, f'design_{name}.yaml')
    with open(designs[name], 'w', encoding='utf-8', newline='\n') as fh:
        fh.write(text)

print('lexsync', lexsync.__version__)
for name, path in designs.items():
    res = lexsync.run_pipeline(path, schema_path, out, verbose=False)
    for p in [res['stimuli'], res['descriptives'], res['comparisons'],
              *res['experiments'].values()]:
        print(f'{os.path.basename(p):42s} {sha256(p)}')

The byte-level guarantee holds for the standardised Euclidean, joint and continuous matching methods. The Mahalanobis and optimal methods depend on each platform’s linear algebra, agree closely and are labelled as approximate in the datasheet. The bundled lexica, derived from wordfreq (Speer, 2022), carry proper nouns and no part-of-speech information, so a real study would join a norm table or supply its own candidate pool, which the design file allows through the items block.
