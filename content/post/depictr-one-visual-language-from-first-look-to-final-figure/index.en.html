A paper’s figures are made at different moments with different tools. The density plot from the first afternoon with the data has one look, the forest plot of the mixed model another, the diagnostics a third, and the Bayesian posterior, added at a reviewer’s request, a fourth. The reader has to learn four conventions to follow one argument, and the author has to remember, at each stage, which colours are safe for readers with a colour-vision deficiency and which are not. depictr is my attempt to settle these questions once. It provides one theme, one palette and one set of conventions for the plots that an analysis produces from exploration to reporting, every function returns a ggplot2 object that can be refined further, and a checking function measures the finished figure against thresholds for contrast, text size and reliance on colour. A Python package of the same name does the same over plotnine.

The data below are the experiment bundled with the package: 24 participants, 40 items, a semantic-priming manipulation with related and unrelated primes, a visual or auditory presentation and the Zipf frequency of each word, with reaction times and accuracy. The design is what I would expect from a lexical-decision study in my own laboratory, which makes it a fair test of whether the package covers the plots such a study needs.

The first look

Column names can be given bare or quoted, and a legend can be tucked into the corner that a unimodal density leaves empty. The empirical cumulative distribution is the plot I prefer for reaction times, since it is free of bins and the quartiles can be read from it directly.

explore_distribution(lexical_decision, RT, group = condition, type = 'density',
                     legend_inside = TRUE,
                     title = 'Lexical-decision RT by priming condition')

ecdf_plot(lexical_decision, RT, group = condition,
          reference_quantiles = c(0.25, 0.5, 0.75), legend_inside = TRUE,
          title = 'Related primes are faster throughout the distribution')

The model and its estimates

The analysis is a mixed model with crossed random intercepts for participants and items, fitted to the correct trials. The package tidies fitted models from lm, glm and lme4 into one table of estimates with intervals, and the forest plot reads from that table, so the same function serves a regression, a mixed model or a data frame of estimates from elsewhere.

fit <- lmerTest::lmer(RT ~ condition + modality + word_frequency +
                        (1 | participant) + (1 | item), data = correct)
tidy_estimates(fit)
#>                 term  estimate std.error   conf.low conf.high
#> 1        (Intercept) 708.01334 27.253962 654.596553 761.43012
#> 2 conditionunrelated  31.95745  8.119043  16.044418  47.87048
#> 3   modalityauditory  25.34713  8.123180   9.425993  41.26827
#> 4     word_frequency -21.89472  5.860301 -33.380696 -10.40874
term_labels <- c(conditionunrelated = 'Unrelated priming',
                 modalityauditory   = 'Auditory modality',
                 word_frequency     = 'Word frequency (Zipf)')
coefficient_plot(fit, standardise = TRUE, order = 'ascending', labels = term_labels,
                 title = 'Effects on RT per SD of each predictor')

Standardising by the predictor’s standard deviation puts a slope per Zipf unit and a contrast between two categories on one comparable axis, and the axis label records the convention. Predicted values come from the fixed effects with a band from the design matrix and the covariance of the estimates, and the conditional modes of the random effects are drawn as a caterpillar plot, one panel per grouping factor.

effects_plot(fit, 'word_frequency', title = 'Predicted RT across word frequency')

random_effects_plot(fit, title = 'By-participant and by-item departures')

Two specifications can be overlaid on one forest plot to show whether dropping a predictor moves the other estimates, and a fit table collects the usual comparison statistics.

reduced <- lmerTest::lmer(RT ~ condition + word_frequency +
                            (1 | participant) + (1 | item), data = correct)
compare_models(Reduced = reduced, Full = fit, order = 'descending',
               labels = term_labels,
               title = 'Does dropping modality move the other effects?')

Three questions about robustness

A convergence warning from lme4 is best answered by refitting with every optimiser and comparing the estimates, a practice I have written about before. depictr’s plot for that comparison takes a tidy data frame of optimiser, term and value, and the package ships the summary of an allFit() run on this very model, so the figure is drawn without the refits.

af <- readRDS(system.file('extdata', 'allfit_lexdec.rds', package = 'depictr'))
fx <- af$fixef
opt_long <- data.frame(optimizer = rep(rownames(fx), times = ncol(fx)),
                       term = rep(colnames(fx), each = nrow(fx)),
                       value = as.vector(fx))
rownames(fx)
#> [1] "bobyqa"                        "Nelder_Mead"                  
#> [3] "nlminbwrap"                    "nmkbw"                        
#> [5] "optimx.L-BFGS-B"               "nloptwrap.NLOPT_LN_NELDERMEAD"
#> [7] "nloptwrap.NLOPT_LN_BOBYQA"
optimizer_fixef_plot(opt_long, labels = term_labels,
                     title = 'Fixed effects across seven optimisers')

The second question is what a Bayesian version of the model says. The package bundles a thousand draws from the posterior of the same model fitted with brms, and the plot overlays the frequentist estimate on the full posterior of each term, with a note that the frequentist analysis had no prior. The posterior can also be drawn on its own, with a region of practical equivalence and the probability of direction annotated per parameter (Kruschke, 2018).

draws <- readRDS(system.file('extdata', 'lexdec_draws.rds', package = 'depictr'))
dim(draws)
#> [1] 1000    4
frequentist_bayesian_plot(fit, draws, intercept = FALSE,
                          note_frequentist_no_prior = TRUE, labels = term_labels,
                          title = 'Frequentist estimate over the Bayesian posterior')

slopes <- draws[c('conditionunrelated', 'modalityauditory', 'word_frequency')]
posterior_plot(slopes, style = 'halfeye', rope = c(-5, 5), pd = TRUE,
               labels = term_labels,
               title = 'Fixed-effect posteriors (ms), with ROPE and pd')

Diagnostics that know what they are looking at

The diagnostics function recognises the class of the model. For a binomial model of accuracy it draws binned residuals (Gelman & Hill, 2007) and a quantile-quantile plot of randomised quantile residuals (Dunn & Smyth, 1996), with a seed so that the randomisation is reproducible, in place of the panels that suit a linear model.

gfit <- glm(accuracy ~ word_frequency + condition + modality,
            data = lexical_decision, family = binomial)
residual_diagnostics_plot(gfit, seed = 1, title = 'Accuracy model: GLM diagnostics')

The audit

The palette is the eight colours of Okabe and Ito (2008), and the package checks them the way it checks any palette, by the CIE76 colour difference between every pair under normal vision and under each dichromacy simulated at full severity with the model of Machado et al. (2009). A palette that passes is not yet a safe figure, so a second function inspects a built plot and reports nine measurements beside their thresholds.

Two rows fail on the default two-colour density. The orange sits at a contrast of about 2.25 to 1 against white, where the guideline for graphical objects asks for 3 to 1, and colour alone distinguishes the conditions. Both are mended in one line, by swapping in the darker vermillion and adding line type as a redundant channel, since the plot is an ordinary ggplot2 object. Text drawn for a 17.8 cm figure arrives at half its size in an 8.9 cm journal column, and the check can be run at that width.

The package states the limit of its guarantee beside the claim. The eight colours pass every colour-vision check and fail in greyscale, where orange and sky blue differ by less than one unit of lightness, so a figure that may be printed in black and white needs a second channel as well.

Composition and the Python twin

Panels are composed with duplicate legends collected, an overall title and tags, and the package options set the base size and the accent colour once for every theme, scale and plot.

p_coef <- coefficient_plot(fit, order = 'ascending', labels = term_labels)
p_fbp <- frequentist_bayesian_plot(fit, draws, intercept = FALSE, labels = term_labels)
arrange_plots(p_density + labs(title = 'A first look'),
              p_coef    + labs(title = 'Mixed-model estimates'),
              p_fbp     + labs(title = 'Posterior with frequentist overlay'),
              p_mended  + labs(title = 'Audited and mended'),
              ncol = 2, title = 'One visual language, from exploration to audit',
              tag_levels = 'A')

The Python package uses the same function names and the same thresholds. The R session writes the data, the density audit and the colour-vision simulation to disk, and the Python session reads the data, repeats the audit and the simulation and compares. The mixed model is the one place where the engines differ by construction, lme4 against statsmodels, so the comparison below uses an ordinary regression on the correct trials, which both fit identically once the reference level of the categorical predictor is set to match.

write.csv(lexical_decision, file.path(parity_dir, 'lexical_decision.csv'), row.names = FALSE)
write.csv(check_figure(p_density), file.path(parity_dir, 'audit_R.csv'), row.names = FALSE)
writeLines(simulate_cvd(depictr_palette(), 'deutan'), file.path(parity_dir, 'deutan_R.txt'))
ols <- lm(RT ~ condition + modality + word_frequency, data = correct)
write.csv(tidy_estimates(ols), file.path(parity_dir, 'ols_R.csv'), row.names = FALSE)
import os
import numpy as np, pandas as pd
import statsmodels.formula.api as smf
import depictr as dp

parity = os.environ['DEPICTR_PARITY']
ld = pd.read_csv(os.path.join(parity, 'lexical_decision.csv'))
correct = ld[ld['accuracy'] == 1]

audit_py = dp.check_figure(dp.explore_distribution(
    ld, 'RT', group='condition', kind='density', legend_inside=True))
audit_r = pd.read_csv(os.path.join(parity, 'audit_R.csv'))
deutan_r = open(os.path.join(parity, 'deutan_R.txt')).read().split()
# R's factor keeps the levels of `modality` in the order 'visual', 'auditory';
# pandas reads the column as text and patsy would sort it alphabetically, which
# would silently flip the sign of that contrast. The reference is set explicitly.
formula = ("RT ~ condition + C(modality, Treatment(reference='visual')) "
           "+ word_frequency")
ols_py = dp.tidy_estimates(smf.ols(formula, data=correct).fit())
ols_r = pd.read_csv(os.path.join(parity, 'ols_R.csv'))

print('depictr', dp.__version__)
print('audit verdicts identical:', audit_py['verdict'].tolist() == audit_r['verdict'].tolist())
print('audit measurements within 0.005:',
      np.allclose(audit_py['measured'].astype(float), audit_r['measured'].astype(float), atol=0.005))
print('deuteranopia simulation identical:',
      dp.simulate_cvd(dp.depictr_palette(), 'deutan') == deutan_r)
print('OLS estimates and intervals within 1e-6:',
      np.allclose(ols_py[['estimate', 'conf_low', 'conf_high']].to_numpy(),
                  ols_r[['estimate', 'conf.low', 'conf.high']].to_numpy(), atol=1e-6))

What the package does not do is also worth saying. It does not fit models, so the choice of model, contrasts and priors remains the analyst’s, and the plots show what was fitted. The colour-difference thresholds are conventions, and the audit reports measurements against them so that a different threshold can be applied. Beyond eight categories the palette interpolates and warns, and the guarantee lapses, which is one more reason to prefer facets to colour when a figure has many groups.
