Psychological theories are mostly written in prose, which does not let their structure be checked mechanically. Whether a theory forbids anything, whether its predictions follow from its propositions, whether an amendment made after a failed test adds content or merely protects the theory, whether two constructs are the same idea under two names: these questions have answers, and the literature on theory appraisal from Meehl (1990) onwards has said what they are, but nothing in the way theories are written down lets the answers be computed. theoryforge stores a theory as a small document, a YAML or JSON file with constructs, propositions, predictions, alternatives and provenance under a published schema, and then validates it, tests it, versions it and diffs it. The R and Python packages implement the same specification and produce the same artefacts, as the final section shows.

The theory used throughout is the one bundled with the package that is closest to my own work: an account of modality switching in grounded conceptual processing, the finding that verifying a property of a concept in one perceptual modality is slower after a property in a different modality (Pecher et al., 2003), read as evidence that conceptual access recruits modality-specific systems (Barsalou, 1999). A second bundled theory, a network model of panic disorder with a feedback loop, serves as the contrast case at the one step where cycles matter. The Python package is on PyPI and the R one is installed from GitHub, which also hosts the R and Python documentation and a set of browser apps.

Validation at two levels

Validation runs at two levels. The structural pass checks required fields, enumerations and, since version 0.6.0, unknown keys at the top level, which matters because a misspelt collection used to be dropped silently and moved the rigour score. The full pass adds referential integrity, so that a prediction cannot be derived from a proposition that does not exist.

tf_validate(switching, full = TRUE)
misspelt <- switching
names(misspelt)[names(misspelt) == 'predictions'] <- 'predicitions'
tryCatch(tf_validate(misspelt), error = conditionMessage)

#> [1] "invalid theory object: prediction[0] derives_from 'p_missing' is not a known proposition"

The rigour checklist

The checklist has 12 items with weights that sum to one, drawn from the literature on what makes a theory appraisable, and two of them are blockers: a theory that forbids nothing, or whose predictions do not derive from its propositions, fails the gate whatever else it scores. Each item carries the citation that motivates it. The score indexes how completely a theory is specified against the checklist, which the package’s documentation is careful to distinguish from whether the theory is true.

rep <- tf_check(switching)

The diagram

Every diagram view is deterministic text, in DOT, in dagitty syntax or in SVG, which a website can render and a version-control system can diff. The theory object is plain data, so a Mermaid flowchart, which this site renders in the browser, can be produced by a short helper function.

cat(tf_diagram(switching, type = 'causal_dag'))
#> dag {
#>   c_sensorimotor_experience -> c_modality_activation
#>   c_modality_activation -> c_switch_cost
#>   c_modality_activation -> c_conceptual_access
#>   c_lexical_familiarity -> c_conceptual_access
#> }
tf_mermaid <- function(theory) {
  esc <- function(s) gsub('"', "'", s, fixed = TRUE)
  lines <- 'flowchart LR'
  for (c in theory$constructs) lines <- c(lines, sprintf('  %s["%s"]', c$id, esc(c$label)))
  for (p in theory$propositions) {
    lines <- c(lines, sprintf('  %s -->|%s| %s', p$from, p$relation, p$to))
  }
  paste0(paste(lines, collapse = '\n'), '\n')
}

What the theory forbids

A causal graph implies a set of conditional independencies, and the shortest complete statement of what a theory forbids in data is the basis set of those independencies, which for an acyclic graph with k constructs and m edges has k(k − 1)/2 − m members. The panic network has a feedback loop, so it has no basis set, and the function says which cycle is responsible.

impl <- tf_implications(switching)
c(acyclic = impl$acyclic, edges = impl$n_edges, implications = impl$n_implications)
#>      acyclic        edges implications 
#>            1            4            6

The implications can be cross-checked with dagitty from the package’s own export of the graph, and they are empirical claims. Below, one observed variable per construct is simulated from the theory’s own graph and from a rival world in which lexical familiarity is partly caused by sensorimotor experience, which is what a symbol-interdependency account of conceptual processing would allow. dagitty’s local tests score every implied independence as a partial correlation in both worlds.

g <- dagitty::dagitty(tf_diagram(switching, type = 'causal_dag'))
all(vapply(impl$implications, function(x)
  dagitty::dseparated(g, x$a, x$b, unlist(x$given)), logical(1)))

set.seed(2026)
n <- 4000
sim_world <- function(rival = FALSE) {
  E <- rnorm(n)
  Fm <- if (rival) 0.5 * E + rnorm(n) else rnorm(n)

  S <- 0.6 * A + rnorm(n)
  C <- 0.5 * A + 0.5 * Fm + rnorm(n)
  data.frame(c_sensorimotor_experience = E, c_modality_activation = A,
             c_switch_cost = S, c_conceptual_access = C, c_lexical_familiarity = Fm)
}

From the graph to a fitted model

The same graph compiles to lavaan syntax, with a measurement model for each construct and the structural paths the propositions assert. The compiled model is fitted below to data simulated from a population version of itself, and the third basis-set claim is imposed as a restriction and tested against the free model.

How risky are the predictions

A prediction that could hardly fail provides little corroboration, which is what the severity rubric scores. It scores each prediction by its type, from a bare existence claim to a point prediction, discounts directional predictions by Meehl’s crud factor and adds credit for naming a registered rival. The preregistration export turns the theory into the skeleton of a registration, with the predictions, their severities and the outcomes that would count against them.

Progressive and degenerating amendments

Lakatos distinguished progressive amendments, which add content that survives a test, from degenerating ones, which add an assumption to protect a prediction that failed (Lakatos, 1978). The appraisal function makes that distinction on two versions of a theory. The package’s own pair of panic-network versions is progressive, since the second adds a prediction that was later corroborated. Two amendments of the modality-switching theory show both outcomes: an auxiliary assumption that protects a prediction with no passing test in sight, and a new prediction about the N400 in EEG, derived from the existing propositions and recorded as passed.

The rigour score falls slightly from the first version to the second, and the table shows where. Several items are ratios over the set of predictions, so a fifth prediction that is directional, and whose severity of 0.5 sits below the mean of the four it joins, moves each of them down a little. A theory that gains content can therefore lose points on a checklist, which is a reminder that the score measures how completely a theory is specified and not how good it is. Every builder verb logs a provenance entry, so the history of the document records who changed what and when, and the version block records the lineage.

A checksum for each version

The dossier is a Markdown summary of the whole theory, and because it is byte-identical between the R and Python packages, its checksum serves as a language-independent identifier of the theory’s state, which the version block can carry. The amended theory is written out, read back and found unchanged.

write_raw <- function(s, name) {
  path <- file.path(out_dir, name)
  writeBin(charToRaw(enc2utf8(s)), path)
  path
}
dossier_v1 <- write_raw(tf_dossier(switching), 'modality-switching-2026.dossier.md')
unname(tools::md5sum(dossier_v1))
#> [1] "2c314f0651ebbaf42d668f692fd88a39"
dossier_v2 <- write_raw(tf_dossier(switching_v2), 'modality-switching-2026-v2.dossier.md')
switching_v2$version$content_hash <- unname(tools::md5sum(dossier_v2))
tf_write(switching_v2, file.path(out_dir, 'modality-switching-2026-v2.theory.yaml'))
back <- tf_read(file.path(out_dir, 'modality-switching-2026-v2.theory.yaml'))
c(valid = isTRUE(tf_validate(back, full = TRUE)),
  same_dossier = identical(tf_dossier(back), tf_dossier(switching_v2)))
#>        valid same_dossier 
#>         TRUE         TRUE

Beyond the artefacts shown here, the package writes a Quarto report, deposits a dossier on OSF from a dry run that can be inspected before anything is sent, simulates the construct network as a dynamical system, and maps a bibliographic corpus around a theory to point out topics that the theory does not yet address, with corpora that the scopusflow package can supply. The checklist remains a structural and lexical screen. It can say that a theory forbids something and that its predictions follow from its propositions. Whether the theory is true is for the tests that the document now makes easier to specify.
