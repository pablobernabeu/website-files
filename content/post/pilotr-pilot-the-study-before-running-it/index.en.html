Most experiments in psycholinguistics cross participants with items, and the analysis that respects that structure is a mixed model with random intercepts and slopes for both (Barr et al., 2013). No formula gives the power of such an analysis. The power depends on the number of participants and of items, on the variance of each source of variation, on the correlations between intercepts and slopes and on the response distribution, and the only way to learn it is to write down the design and simulate it many times (DeBruine & Barr, 2021). Doing so before the study rather than after is the difference between a plan and an excuse, and it is also a chance to see the data that the design would produce and to catch a mistaken assumption while it is cheap.

pilotr makes the design the unit of work. A design is a specification, a small JSON document with the units, the factors, the predictors, the fixed effects, the random effects and the response family, which is validated before anything is simulated. The same specification produces a data set, the formula of the analysis it implies, a power analysis with Type S and Type M errors (Gelman & Carlin, 2014), a precision analysis against a region of practical equivalence, and a set of scripts that reproduce the whole exercise. The R and the Python packages read the same specification and, given the same seed, generate the same data, which the post checks at the end.

library(pilotr)
library(ggplot2)
packageVersion('pilotr')
#> [1] '0.3.0'

The design, written once

The experiment is a semantic-priming lexical-decision task: 30 participants, 24 target words, each seen with a related and an unrelated prime. Reaction times follow a shifted lognormal distribution, 200 ms plus a lognormal component, so the effects are on the log scale, where an intercept of 6 puts the typical response near 600 ms and a priming effect of 0.05 is a slowing of about five per cent for unrelated primes. Two continuous predictors enter, the frequency of the target word at the item level and the vocabulary of the participant at the participant level, the latter measured with a reliability of 0.8, which is what a vocabulary test delivers. A cross-level interaction lets priming grow with vocabulary. Both participants and items have random intercepts and random priming slopes, with their correlations.

spec <- list(
  spec_version = '0.3',
  name = 'semantic_priming_ldt',
  seed = 90210,
  units = list(subject = list(n = 30), item = list(n = 24)),
  factors = list(list(
    name = 'prime', levels = c('related', 'unrelated'),
    contrasts = list(prime = c(-0.5, 0.5)),
    vary_within = c('subject', 'item'))),
  predictors = list(
    list(name = 'z_freq',  varies_by = 'item',    mean = 0, sd = 1),
    list(name = 'z_vocab', varies_by = 'subject', mean = 0, sd = 1, reliability = 0.8)),
  fixed = list(
    intercept = 6.0,
    coefficients = list(prime = 0.05, z_freq = -0.03, z_vocab = -0.02,
                        `prime:z_vocab` = 0.02)),
  random = list(
    subject = list(intercept_sd = 0.12, slopes = list(prime = 0.04),
                   correlations = list(`intercept,prime` = 0.2)),
    item    = list(intercept_sd = 0.08, slopes = list(prime = 0.02),
                   correlations = list(`intercept,prime` = -0.1))),
  response = list(family = 'shifted_lognormal', name = 'RT', sigma = 0.30,
                  shift = 200, round = 4))
validate_spec(spec)

Validation is there because a mistyped key would otherwise be ignored, and the design would be simulated without the effect it was meant to test.

bad <- spec

Because the specification gave both participants and items random priming slopes, each participant and each item has its own priming effect, which is the variation that the analysis has to account for and that a formula ignores.

unit_effects <- function(unit) {
  m <- tapply(pilot$RT, list(pilot[[unit]], pilot$prime), mean)
  data.frame(unit = unit, id = rownames(m), effect_ms = m[, 'unrelated'] - m[, 'related'])
}
effs <- rbind(unit_effects('subject'), unit_effects('item'))
effs$id <- factor(effs$id, levels = unique(effs$id[order(effs$unit, effs$effect_ms)]))

The anatomy of the design

The specification implies a decomposition of the variance of the linear predictor and an analysis model, and both can be read off it before any data exist.

round(unlist(response_variance(spec)), 4)
#>    fixed  subject     item residual    total 
#>   0.0021   0.0148   0.0065   0.0900   0.1134
model_formula(spec)
#> .y ~ prime + z_freq + z_vocab + prime_z_vocab + (1 + prime | 
#>     subject) + (1 + prime | item)

Whether a simulation recovers the parameters that went into it is the check that DeBruine and Barr (2021) recommend before trusting a power analysis. One large simulated study fitted with the implied model recovers the fixed effects and the variance components, with the vocabulary slopes attenuated by the square root of the reliability, as they should be.

big <- spec
big$units$subject$n <- 80
big$units$item$n <- 60
fit <- suppressMessages(lmerTest::lmer(
  model_formula(spec), data = model_data(spec, simulate_design(big)),
  control = lme4::lmerControl(calc.derivs = FALSE)))
truth <- c(`(Intercept)` = 6, prime = 0.05, z_freq = -0.03, z_vocab = -0.02,
           prime_z_vocab = 0.02)
data.frame(specified = truth,
           recovered = round(lme4::fixef(fit)[names(truth)], 4),
           se = round(sqrt(diag(as.matrix(vcov(fit))))[names(truth)], 4))
#>               specified recovered     se
#> (Intercept)        6.00    5.9986 0.0175
#> prime              0.05    0.0608 0.0081
#> z_freq            -0.03   -0.0319 0.0092
#> z_vocab           -0.02   -0.0072 0.0156

Power, and what a significant result would look like

Simulation-based power at the planned sample refits the implied model on each replicate and counts. The report includes the Monte Carlo standard error, a Wilson interval, the number of fits that were singular, which are counted and not dropped, and for each effect the Type S error, the share of significant estimates with the wrong sign, and the Type M error, the average factor by which significant estimates exaggerate the true effect.

pw <- power_mixed(spec, n_sims = n_sims, workers = workers)
pw

With 30 participants and 24 items, the maximal model is richer than the design supports, and many replicates end in a boundary fit. The priming effect has reasonable power; the interaction with vocabulary, which is what a researcher would most want to claim, does not, and the estimates of it that would reach significance are exaggerated by a factor of two or more. A sweep over effect sizes, with a null condition, shows the false-positive rate of the planned analysis and how the exaggeration recedes as power grows. The base coefficients are carried along explicitly, since the sweep replaces the block of coefficients as a whole.

grid <- design_conditions(prime = c(0.03, 0.05, 0.08), .null = TRUE,

How many participants

A power curve over the number of participants is solved for the sample that reaches 80% power by a binomial regression of power on the square root of the sample size, weighted by the replicates behind each point, with an interval from the delta method. The solver refuses to extrapolate beyond the simulated range.

Power answers whether an effect would be detected. A different question is whether the study could tell a priming effect from a negligible one, which is what a region of practical equivalence (ROPE) formalises (Kruschke, 2018). With a ROPE of ±0.02 on the log scale, about 8 ms, the precision analysis asks how often the 95% interval would fall entirely outside the region, and solves the curve for the sample that reaches 80%.

prc <- precision_curve(spec, focal = c(prime = 0.05),

The sample that detects the effect is well below the sample that pins it down, which is the usual finding and the reason to plan for precision when the size of an effect matters more than its existence.

The artefacts

A plan is only useful if someone else can rerun it. The specification is written as JSON, an R script that embeds it at full precision is generated, the confirmatory brms model that the specification implies is written out with its formula, family and priors, and a Bayesian design analysis with a Savage-Dickey Bayes factor and a ROPE decision can be emitted as a script for a cluster. The replicate seeds come from a generator shared with the Python package.

The same bytes from Python

The two packages implement the same generator over the same specification, down to the order in which random deviates are drawn. The R session writes the simulated pilot data with every value at 17 significant digits and hashes it, and the Python session reads the specification, simulates and hashes the same format. The function names differ slightly, simulate_design() in R against simulate() in Python, since each follows its own language’s conventions.

cell <- function(v) if (is.character(v)) v else sprintf('%.17g', as.numeric(v))
dump17 <- function(d, path) {
  con <- file(path, open = 'wb'); on.exit(close(con))
  cols <- lapply(d, function(col) vapply(col, cell, character(1), USE.NAMES = FALSE))
  lines <- c(paste(names(d), collapse = ','),
             vapply(seq_len(nrow(d)), function(i)
               paste(vapply(cols, `[`, character(1), i), collapse = ','), character(1)))
  writeLines(lines, con, sep = '\n')
}
dump17(pilot, file.path(out_dir, 'r_dump.txt'))
unname(tools::md5sum(file.path(out_dir, 'r_dump.txt')))

import hashlib, json, os

    spec = json.load(fh)

data = pilotr.simulate(spec)

def cell(v):
    return v if isinstance(v, str) else format(float(v), '.17g')

lines = [','.join(data.columns)]
lines += [','.join(cell(row[c]) for c in data.columns) for row in data.rows]

Two cautions apply to everything above. Fifty replicates per point are enough to show the shape of the curves in a post and far too few for a plan, where two hundred or more are the norm and the Monte Carlo standard error is the quantity to watch. The specification also encodes assumptions, in particular the random-effect variances and correlations, that a real pilot or a published data set should supply, and the reverse direction from a fitted model exists for that reason.
